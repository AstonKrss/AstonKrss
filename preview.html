精选项目

各自的难点在哪

ChatServer —— 手写三个协议栈。 core 是 EventLoop → Poller → Channel → Acceptor / TcpConnection + Timer，protocol 里 HTTP/1.1、WebSocket、SMTP 各自独立解析器，service 再叠用户、消息、频道、好友。 HTTP 侧要处理 Content-Length 与 Connection 语义，WebSocket 要接分片帧和关闭握手，SMTP 是完整的 会话状态机。不用 muduo 自己写一遍，才知道半包该攒在哪。

heartbeatd —— 把内核批量接口吃满。 32 字节 UDP 报文带稳定 host_id + 每次启动新生成的 boot_id + 递增序号，就能区分上线 / 重启 / 超时离线三种事件，不用付 TCP 握手或 ICMP 被封的代价。 4 receiver + 4 worker，loopback 压到 116 万 pps 零丢包，p99 < 500 µs；kernel_dropped （该调 SO_RCVBUF）和 queue_dropped（该加队列或加 worker）分开计数，因为排查方向完全不同。

HoloData-PII-Scanner —— 同一条数据，五条路径。 一条身份证号可能藏在 MySQL 的 TEXT 字段、 导出的 JSON、Base64 编码的附件、一张扫描件图片，或者被拆成几段写进日志正文。七个扫描器 （结构化 / 半结构化 / 编码 / 文本 / OCR / 数据库对象 / SQL 遍历）共用一套「正则 + 校验码 → 分级」 的判定，模型用的是 CRF 与 BiLSTM-CRF，图片走 PP-OCRv4。工程上最难的是别把样本数据带出门： 仓库里连 data/、output/、logs/ 都进 .gitignore，因为扫描器自己就是最危险的泄露源。

travel-agent —— 把一次差旅拆成 8 个节点。 意图识别用便宜的小模型，推理交给大模型； 政策校验走 RAG 检索企业差旅制度；一旦超预算就中断流程等人审批，审批完从断点恢复； 前端用 SSE 把节点状态和推荐卡片流式推出来。多智能体最容易写成一锅粥，这里是靠显式状态机 （update_state + checkpointer）管住的。
